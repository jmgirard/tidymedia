# Lessons

_Durable, append-only repo lessons (build quirks, testing tricks) — captured at milestone
end, surfaced at plan time. Capped at 50 lines (D-015); prune the least-useful when full.

- 2026-08-06 (M52): a parity baseline is only as good as the fixture family under it. Five fixtures built from lavfi sources carry no side data and no non-ASCII bytes, so a byte-identical-output test over them stayed green while `probe_all()` renamed `rotation` out of existence and dropped a whole stream row on one unreadable byte — both found at review, not by the suite. When a change reworks a parser, build a fixture per INPUT CLASS the parser distinguishes (each nested section, multi-line values, non-ASCII bytes), never per output shape you already understand; and a frozen `.rds` of recorded tool output cannot see across tool versions, so it proves parity only on the version that recorded it.
- 2026-08-06 (M52): FFprobe's two writers disagree about nested-section keys in more than casing. `default=nw=1` prints `TAG:`/`DISPOSITION:` where `-of compact` prints `tag:`/`disposition:` — but side data is BARE under the old writer and `side_datum/<type>:` under the new one, so "uppercase whatever precedes the first `:`" silently renames `rotation`, which essentially every phone video carries. And `default=nw=1` escapes nothing, so any multi-line value — a newline-bearing tag, or the display matrix, which is four lines by nature — becomes invented columns in a one-pair-per-line parser. Diff the two writers' key sets on a file carrying the section you care about before assuming a rename rule.
- 2026-07-13 (M26): a `_batch` verb that auto-derives output paths from the input *basename* silently overwrites when two rows collide — a duplicated input, or same-basename inputs under one shared `outdir`. Guard at the resolved-path level (`anyDuplicated(patterns)`), not just the input level; the older `*_batch` verbs only rejected duplicated inputs.
- 2026-08-06 (M52): R's character-based string functions are locale traps on text a process handed back. `strsplit(x, "", fixed = TRUE)` returns `NA` with only a WARNING when `x` is invalid in the session's `LC_CTYPE`, so whatever the caller derived from it vanishes silently; `sub()` on the same input errors outright. `useBytes = TRUE` fixes both wherever the separators are ASCII and preserves the original bytes — at the cost of dropping the string's UTF-8 `Encoding()` mark, a difference `identical()` and `expect_equal()` cannot see.
- 2026-07-12 (M18): a cli `{?s}` governed by a `{.val {vector}}`/`{cli::qty(vec)}` throws `length(object) == 1` with 2+ items in a multi-line `cli_warn`/`abort`. Drive plurals off a scalar `{length(x)}`; test count messages with 2+ items, as a 1-item test hides it.
- 2026-07-12 (M19): a fast-path branch that skips the shared batch runner (`ffm_batch`) must re-synthesize that runner's *opt-in* outputs (`verified` column, manifest attr) or the return schema silently diverges from the normal path across calls. Trick: subsetting a canonical 0-row schema tibble pads to N all-NA rows for free (`col[rep(NA_integer_, n)]` gives n type-matched NAs). Test parity by comparing `names()`/types of the fast vs the normal path.
- 2026-07-13 (M23, trimmed 2026-07-31 — its `_pkgdown.yml` half is now owned by PROFILE.md's consistency-gate slot): a rename/un-export must also sync live vignette and `@examples` chunks, which fail only at vignette-build. Grep both before dropping `@export`.
- 2026-07-30 (M45, consolidating M27): FFmpeg behavior differs by version and the two CI platforms straddle those differences — macOS brew ships 8.x, ubuntu-latest ships 6.1.1 — so "green locally, red on Ubuntu" is the signature. Two instances paid for: per-stream metadata (`-metadata:s:v:0 title=`) became `name` on 8.x macOS and was absent on Ubuntu, so assert only on the stripped *output*, never an injected tag's *presence*; and the adts muxer rejects a multi-stream `.aac` on 8.1.2 but writes it and exits 0 on 6.1.1, so seven M45 tests that provoked an error through `.aac` caught no condition at all there. When a test needs "the command failed", trigger it with something no build can do (an AAC-to-MP3 stream copy); where the refusal itself IS the subject, probe this ffmpeg and skip. A third platform failure is not the package at all: `pandoc: internal error: ARR_WORDS object (0x...) entered!` crashes vignette re-building on macos-latest arm64 and fails the job with `Status: 1 ERROR` while every test passed — re-run the job before reading it as a regression (M63).
- 2026-07-13 (M28): extracting a shared helper *between* a documented function's `#'` roxygen block and its `fn <- function` line silently re-targets the roxygen to the helper and drops the original's `.Rd` — `document()` warns "Deleting <fn>.Rd". Put the extracted helper ABOVE the roxygen block, not between it and the function.
- 2026-07-26 (M31): skip a hardware-encoder execution test on run-time usability, not merely that the encoder is *listed* — CI lists `h264_nvenc` without a GPU, so probe a 1-frame lavfi encode and skip unless it exits 0. **Extended M63, the converse:** a skip keyed on whether the FIXTURE came out right cannot tell "this platform can't express it" from "the run went wrong", so a mode-000 file that stayed readable silently voided the milestone's whole behavioural evidence with a green check. Enumerate the platforms that genuinely cannot express it (here Windows, whose chmod reaches only the read-only bit, and root, which reads regardless), skip on those, and FAIL everywhere else. **Extended M68, two more ways such a gate fails.** `testthat::fail()` RECORDS a failure and RETURNS (verified directly), so a gate that only fails falls on into the operation it guards and destroys the fixture — a second, misleading failure over the real one; halt with `skip()` after the `fail()`. And the platform may not be able to NAME the fixture rather than not express it: `*` and `?` are illegal in a Windows filename, so a `writeLines()` to `a*.mp4` ERRORS there instead of skipping — build the fixture INSIDE the gate so the platform check owns its creation.
- 2026-07-26 (M32/M37): a `_batch` per-row override *column* skips the scalar argument's guards (`check_number_whole`/range/type), because the column is validated per row by whatever the pipeline happens to run — `check_token` accepts `"TRUE"`. Re-validate each override column per row AND validate the argument at the front door, and test the same bad value with and without the column present; the bug is invisible until a jobs table happens to carry that column.
- 2026-07-26 (M34): guarding a `_batch` override column whose documented `NA` means "unset" — R types an all-NA column *logical*, so an `is.character`/`is.numeric`-only guard wrongly rejects it, while the usual patch `!is.character(x) && !all(is.na(x))` over-corrects and admits an all-NA numeric or Date. Spell it out: `is.character(x) || (is.logical(x) && all(is.na(x)))`, and test both boundaries.
- 2026-07-27 (M35): an execution test proving a stream copy survived must use a source codec that is NOT the output container's default, or copy and re-encode yield the same `codec_name` and the test passes either way. MP3-in-MP4 discriminates (copy keeps `mp3`, an unset codec yields `aac`); the AAC-in-MP4 `make_test_video()` fixture cannot.
- 2026-07-26 (M36): in a cli message `{.val NULL}` renders the *string* `"NULL"` — quoted, reading as a value to pass — and any argument validated by `check_token()` accepts `"NULL"` and forwards it to FFmpeg, so the hint causes a second failure. Write a NULL sentinel as `{.code NULL}`; every other NULL reference in the package already does.
- 2026-07-26 (M36): when a check is hoisted into a two-pass/batch prelude to fail before an expensive analysis phase, hoist *every* check on that argument — hoisting only the one in mind (here `"copy"`, leaving `check_token()` in the Phase-2 pipeline) still burns one analysis pass per row on a typo.
- 2026-07-26 (M37): removing an argument from a `_batch` verb is only half a clean break — the verb's `...` swallows the retired *argument* silently and the N→2N reshape drops a retired *column* silently, so both spellings need a guard naming the replacement. The scalar sibling needs none: with no `...`, R's own `unused argument` covers it.
- 2026-07-26 (M38): an `arg_match()` argument compared before it is resolved silently misreads its own default — `hardware = c("none","nvenc")` against `identical(hardware, "none")` is FALSE, firing a guard on every default call. Resolve at the front door, before any guard or pipeline reads the value. **Extended M59, same family, other end:** `rlang::arg_match()` takes `values` as a PARAMETER, so a checker supplying its own vocabulary calls it — never reaches past it to `arg_match0()`, which takes a STRING and whose own length guard fires first on any longer value, aborting with ITS call and ignoring the `error_call` you passed (`position = c("center","topleft")` was shown ``​`arg` must be a string or have the same length as `values`​`` blamed on `rlang::arg_match0(...)`, worse than the blame being fixed). `arg_match(value, values, error_arg = arg, error_call = call)` reproduces every branch identically — unsupplied default, caller-reordered permutation, multi-element non-permutation, zero length — verified branch by branch against the pre-change signature form.
- 2026-07-26 (M38/M40): a `cli_abort()` remediation hint must be true under the condition that FIRED the guard, not in general — and it goes stale from two directions. Writing it: M38's guard fires only under `hardware = "nvenc"`, where the general-case hint walked a `.webm` caller into an `h264_nvenc`-in-WebM command. Inheriting it: moving a verb onto a SHARED guard imports wording true for every existing caller and false for the new one (`check_batch_codec_col()` said "`NA` to leave the codec unset" where on `convert_audio_batch` `NA` selects `-q:a 0`). Check a hint against the branch that reaches it; parameterize shared wording (`na_means =`) and assert both the true string and the ABSENCE of the default one. **Extended M57:** roxygen is the third route in — one sentence substituted into a family's nine `@param` blocks was true of three of them, since the others REFUSE the case it described as exempt.
- 2026-07-26 (M39): a `_batch` verb's batch-wide argument needs a test naming a NON-default value — asserting only the default passes even when the argument never reaches the fan-out, because the shared pipeline carries the same default. Prove the test discriminates by mutating the fan-out to ignore the argument: it must go red.
- 2026-07-29 (M41): a front-door guard added only to improve a *message* silently reassigns error PRECEDENCE — every check already in that function now reports later than it did, and a caller wrong about two things gets told about the wrong one. Put such a guard at the END of the function's front-door validation, where the value was effectively read before (for a `_batch` verb, just before `ffm_batch()`), and test a call that is invalid in two ways at once; a grid built only from otherwise-valid inputs cannot see the change.
- 2026-07-29 (M41): a before/after grid proves contract-neutrality only over the dimensions it VARIES — three review rounds each found a different unvaried one (a matching `jobs` override column, a malformed `jobs`, then `two_pass`/`width`). Before trusting one, list the arguments it holds fixed, and check that each cell's baseline call actually SUCCEEDS: a cell whose default aborts compares equal on both refs while measuring nothing. **Extended M61, the same failure one level up:** where the criterion demands a CROSS-PRODUCT (each guard x each form x each error it could report instead), a grid supplying it as hand-written cells fails by a combination nobody typed — three rounds, three different missing combinations, each found by a reviewer and none by the grid. Declare the axes once and GENERATE the product, with a reader re-deriving it against the grid's own output; then verify that reader by mutation, because both of M61's first attempts at one were fooled — a variant cell (`audio(low)`) read back to its base value stood in for the guard it merely supplements, and a control validated at error-CLASS grain passed when a verb's other contradiction of the same class fired instead. **Extended M62, the third level:** an axis whose cells all carry the SAME value cannot distinguish a checker that names every offender from one that names the first, nor a duplicate from a count — M62's grid crossed every verb, form and guard while every cell's missing path was one constant string, and it read green through both defects. Vary the value inside a cell, not just the cells; the fix's own regression cells are the axis the grid was blind to, so widen the grid WITH the fix or the fix ships unmeasured. **Extended M64, the normalizer:** the comparison's NORMALIZER is part of the grid — base `sub()` has no lazy quantifier, so a `^.*?(must be ...)` pattern mapped EVERY message to one identical byte and the same-guard comparison passed over any two messages whatsoever; feed a normalizer two messages that must differ before trusting it, or compare whole `ansi_strip()`ed messages and skip normalizing.
- 2026-07-30 (M42): `if (!is.null(x)) check_string(x)` and `check_string(x, allow_null = TRUE)` accept identical values but emit different messages — only the second says "must be a single string or `NULL`". So WIDENING an argument to accept the `NULL` sentinel silently leaves the first spelling telling users `NULL` is illegal on the one argument where it is now the documented escape hatch. When a milestone makes `NULL` legal, change the guard's spelling too, and assert the "or `NULL`" wording; M40's stale-hint lesson is the same failure reached by adding a caller rather than by widening a contract.
- 2026-07-30 (M42): line coverage cannot see an untested *shared* type-guard call — `check_batch_codec_col(jobs, "video_codec")` executed on every existing test of its verb while only its abort branch went unreached, so codecov showed nothing and deleting the line left the whole suite green. To prove such a call is load-bearing on a given verb, delete it and run the suite (M39's mutation trick); the coverage percentage will never tell you.
- 2026-07-26 (M39): adding an override column to a `_batch` verb also falsifies its `@param jobs` prose, which enumerates the honoured columns and closes "Any other columns are ignored" — a reader who believes that adds the column as a note-to-self and silently re-encodes every row. Update the enumeration, not just the new `@param`.
- 2026-07-30 (M43): adding an explicit `-map` REPLACES FFmpeg's default stream selection wholesale, and that default carried one stream of EACH type — so mapping `0:a:0` onto a verb that previously emitted no map silently stops carrying subtitles (and any other type) into containers that accept them. `extract_audio()` to `.mkv` gave audio+subtitle before and audio alone after; audio-only containers hid it completely. When you add a map to make one stream deterministic, enumerate what the old implicit selection was carrying, and pick the output container that can still show the difference.
- 2026-07-30 (M43): a fixture built to prove a stream-selection change can silently defeat itself, because the ffmpeg command that BUILDS it applies the same default selection you are testing — `ffmpeg -i multi.mkv -c copy out.mkv` without `-map 0` keeps ONE audio track, so three attempts to move the DEFAULT disposition onto track 1 produced a single-track file that compared equal on both refs and measured nothing. Assert the fixture's own property (here, the disposition flags via `ffprobe stream_disposition=default`) and skip if it did not take, before trusting any before/after result.
- 2026-07-30 (M44): `cli::cli_warn()`/`cli_abort()` glue-interpolate EVERY bullet in the calling frame, so a bullet built with `sprintf()` from user data executes whatever braces that data contains — a path `my{video}.mkv` ABORTS the call ("could not evaluate cli expression") and `{n}.mkv`, naming a local of the message-building function, silently prints a filename that does not exist. Braces are legal in filenames on every platform. Route user data through a cli field (`{.file {x}}`), which does not recurse into the value, or `gsub("{","{{")` after the `sprintf()`; only a test over a brace-bearing path catches it.
- 2026-07-30 (M44): a mock that `stop()`s to prove a code path is never taken proves NOTHING when the call site wraps its call in `tryCatch(error =)` — the mock's error is swallowed and the test passes either way (M44's `run = FALSE` purity test stayed green with the gate it existed to pin deleted). Count invocations in the mock and assert the count. And commit the baseline before mutation-probing: `git checkout <file>` restores from the index, so probing uncommitted work reverts the feature itself and every mutation reads red for the wrong reason — the tell is several different mutations producing an identical failure set. **Extended M63:** mutate the FILE, not the namespace. `assignInNamespace()` after `devtools::load_all()` reaches the package's own internal calls but NOT a test's direct call to that internal — `load_all(export_all = TRUE)` put a COPY on the search path — so a wording mutation reddened 3 tests through the verbs while 10 tests calling the checker directly stayed green, understating the guard's reach and reading as weak coverage. **Extended M67:** introducing a session-scoped memo silently voids every counting guard downstream of it, because a guard's OWN earlier call warms the memo — `test-nvenc-docs.R` proved "a stream-copy call aborts without probing" with a control call above it, and once the answer was remembered its trailing `expect_identical(probes, 0L)` held whether or not the measured calls reached the probe at all. Sweep every test that counts calls to a newly-cached function and discard the cache before each measured call; the tell is that the assertion still passes with the abort it fences deleted. And `expect_no_error(expr, message = "my label")` does NOT label the failure — `message` is passed through as the matcher's REGEXP, so an abort whose text does not match records no expectation at all and propagates, killing the loop it sits in and leaving the remaining cases unmeasured (measured on testthat 3.3.2: 0 expectations recorded, `error = TRUE`). Catch the condition and assert on it if you want a labelled, non-fatal per-case control.
- 2026-07-30 (M46): `-shortest` tracks the shortest stream INCLUDING subtitles, so on a fixture whose `.srt` is shorter than its lavfi sources it silently truncates the output (1.021 s against 2.023 s here) — and beside a MAPPED subtitle stream it deadlocks FFmpeg outright, intermittently: the same command hung 10 times in 25 runs on 8.1.2/macOS, 0 in 15 without the flag, 0 in 15 with the flag but no subtitle map. On a fixture built from `duration=`-bounded lavfi sources the flag buys nothing, so drop it; if you keep it, know it is a truncation, not a no-op.
- 2026-07-30 (M46, trimmed M69): R translates the `system(..., timeout =)` warning, so muffling or detecting a timeout by matching its English text is locale-dependent — under `LANGUAGE=de` it reads "Zeitüberschreitung bei Kommando ..." and the match fails, letting the warning through with the FULL command line and its temp paths in it. Key off the `status` attribute (124) instead. M69 built that into `R/timeout.R` and fenced THAT file with a guard that reddens on any text-matching call in it, so the uncovered remainder is any NEW timeout classification written outside it.
- 2026-07-30 (M47): a verb that STATES its stream selection must tolerate an input that lacks the stream type, because FFmpeg treats an unmatched `-map` as fatal, not empty. A bare `-map 0:a` exits 234 ("Stream map '' matches no streams") on a video-only input and a bare `-map 0:v` does the same on an audio-only one — both ordinary research files, and both cases where emitting NO map exited 0 and passed the stream through. Suffix the UNSELECTED specifiers with `?`; leave a specifier the caller NAMED strict, so a mistyped index stays an error instead of silently yielding a stream-less output. The suite caught only the video-only half, via one test that happened to use a silent fixture. **Corrected M49:** the `?` is safe only while ANOTHER map can still match — when EVERY specifier is optional and none matches, FFmpeg discards the maps and reverts to default selection (`-map 0:a:5?` on a video+audio file writes video AND audio), so on a verb emitting ONE map the `?` silently restores the very heuristic the map was added to remove. A one-map verb wants a strict specifier and a loud failure; a multi-map verb keeps the `?`. And `?` never covers a muxer that REFUSES a stream, only an absent one: `-map 0:v?` into `.wav` exits 234.
- 2026-07-30 (M47, extends M41; absorbs M45's reshaped-index line; corrected M48): "last in the front door" is not "last overall" on a verb whose other arguments are validated inside its pipeline — on `anonymize_video`, whose front door holds three checks while `regions`, `color`, both codecs and `pixel_format` are checked in the pipeline, a guard at the end of the front-door block still preceded all of them. So list what the pipeline validates before adding one. But the converse M47 drew — "if the pipeline threads `call`, the front-door copy buys no blame, so omit it" — holds ONLY where the verb calls its pipeline DIRECTLY (proven false at M48 F1). A fan-out verb routes through `ffm_batch()` -> `purrr::pmap()`, so the pipeline's `caller_env()` lands on the anonymous closure and the abort reads "Error in `purrr::pmap(jobs, .f, ...)` / In index: 1"; a verb that RESHAPES its jobs table further reports an index of the reshaped table rather than the caller's row (M45: a 2-row table blamed "In index: 3"). Both shapes need the front-door guard; M57's nine-verb sweep now enforces that half, reddening exactly the verb whose guard is removed. **Extended M57:** a grep for the pipeline's own `cli_abort()` sites UNDER-counts what such a guard displaces, because it attributes an abort to the function that writes it — a check the pipeline reaches through a helper (`check_regions()`, `ffm_crop()`), or one living in the batch closure, is invisible to it and was reassigned unmeasured on four verbs. **Extended M56:** a guard placed AFTER a step that rewrites the value checks the rewritten value, not the user's — `standardize_pipeline()` resolved `video_codec` before the seam, so `resolve_hw_encoder()` turned `"libx264 -evil"` into the clean token `"h264_nvenc"` and the malformed value compiled. And a batch verb's `jobs` COLUMN needs the same front-door treatment its scalar argument does; the site is the shared column guard, never a frame threaded into the fan-out closure.
- 2026-07-30 (M47): a fixture whose property under test COINCIDES with the default makes the test pass with the feature deleted. Proving a verb stopped consulting FFmpeg's DEFAULT-disposition heuristic needs the disposition moved OFF track 0 — otherwise "the heuristic picked it" and "track 0 was picked" are the same observation, and asserting the second proves nothing. Distinct from M43's trap, where the fixture silently failed to take: here it takes perfectly and still measures nothing. Pick a target value no default path can produce (here track 2, `fra`).
- 2026-07-30 (M48): a verb's BRANCHES need not emit the same command shape, and writing about "the verb" hides it — `segment_video()` emitted `-map 0` on its copy branch and NO map on its default re-encode branch, so it carried every audio track one way and one disposition-chosen track the other. The plan, a D-entry, the first NEWS draft and the milestone's own new tests all called it a `-map 0` verb, while the pre-existing map-count invariant had pinned `segment_video(reencode = TRUE) = 0L` in plain sight the whole time. Enumerate each branch's compiled command before writing one sentence about the verb, and read the invariant table you already have: it is evidence about current state, not decoration.
- 2026-07-31 (M50): re-baselining a rendered form across the suite silently voids NEGATIVE assertions. `expect_false(grepl("-map 0 ", cmd))` and `expect_no_match(cmd, "-map a")` keep passing once the rendering changes — they now refute a string nothing can produce, so the regression they were written to catch walks straight through. Seven of them existed here. Sweep the negatives explicitly and by hand: the suite going green is not evidence for them, it is the failure mode. A prefix probe (`-map "0:a:`) keeps no closing quote, or it matches nothing.
- 2026-07-31 (M50): a scripted sweep over test files must parse the value with a GRAMMAR, never as "the next token". `[^[:space:]]*` after `-map ` is greedy past the enclosing string literal's closing quote, so `"... -map 0", fixed = TRUE)` rewrites into broken R that the file's own tests then cannot even parse; and the escape form differs by delimiter (`\"` inside a double-quoted literal, `"` inside a single-quoted one), so the transformer must track string state. Two classes look identical to it and must be excluded: `test_that()` titles, and FIXTURE INVOCATIONS (`helper-media.R`, `run_ffmpeg_fixture()`) — commands FFmpeg executes, not expectations about a compiled form. Review caught one of those that slipped.
- 2026-07-31 (M50): snapshot expectations are NOT compared under `testthat::test_file()` after `devtools::load_all()` — the test reports 0 passed and 0 failed and writes no `.new` file, so a stale snapshot reads as a clean run. Only `devtools::test()` (a real package context) records and compares them. Verify any snapshot-bearing change with `devtools::test()`, and treat a `test_file()` green as silent on that assertion.
- 2026-07-31 (M51, extended M59): a test that reads `man/*.Rd` from the source tree SKIPS under `R CMD check`, where tests run against an INSTALLED package that has no `man/` — so a documentation guard written that way is green in CI while never actually running, and looks healthy locally because `devtools::test()` does have the source tree. Read `tools::Rd_db("tidymedia")` as the fallback: same content by the installed route, so the guard runs in both shapes. Verify it did by comparing the check run's pass/skip totals against the local run's — identical totals mean it ran, a higher SKIP means it did not. And keep the source-tree path to `../../man` exactly: a `../../../man` fallback resolves, from `<pkg>.Rcheck/tests/testthat`, to the directory HOLDING the `.Rcheck` dir, so a check run inside the package source silently validates the working tree instead of the tarball under check. **Extended M59: the same trap catches `../../R`, and there the fallback is different.** A guard globbing the SOURCE dir to prove a code invariant — "this literal appears once" — finds only the lazy-load DB under check and skips, so the invariant is unenforced in exactly the run the release gate uses. Read the NAMESPACE instead: `mget(ls(asNamespace(pkg), all.names = TRUE))` filtered to functions gives every body, and `formals()` gives every default, in both shapes. Deparsing them also normalizes quoting, spacing and line-wrapping, so the guard stops pinning source FORMATTING — a literal grep would have missed a copy written `c('a','b')` or wrapped across lines. And prefer asserting AGREEMENT over uniqueness where copies are deliberate: evaluate each default and compare it to its single source, which catches a reordered or differently spelled copy that is still wrong.
- 2026-08-06 (M53): fanning a NON-EXPORTED function out with furrr is correct in the shipped package and broken under `devtools::load_all()`. `furrr::future_map(x, probe_one)` serializes the closure, whose enclosing environment the worker rebuilds by `loadNamespace()` — from the INSTALLED library, so under `load_all()` the worker cannot see a source-only internal at all (`could not find function "parse_compact_probe"`), and where the package IS installed it silently runs the installed version of your edits. `ffm_batch(parallel = TRUE)` does not hit this, because the function it maps is the caller's own `.f`, so the trap is specific to mapping a package internal and does not show up as a package-wide devtools quirk. The suite cannot catch it either: under the default sequential plan `future_map()` never leaves the process. Verify a new fan-out against a real `plan(multisession)` on an `R CMD INSTALL`ed copy, not via `load_all()`, and pin the plan inside the tests so an ambient one cannot silently change which path they exercise.
- 2026-08-07 (M54, extended M58): a test that reads an error to prove WHICH call is blamed passes for the wrong reason on a malformed input, because the argument checks share the same `call = call` the feature under test threads — so a bad `regions` or a missing jobs column aborts blaming the same front door and satisfies the expectation with the feature deleted. Three review rounds paid for it: two blame controls and one `_batch` measurement each read a schema error as correct attribution, and the one that produced a NEWS claim shipped it. Assert WHICH failure, never that one occurred — match the message before reading `conditionCall()` — and verify a jobs-table call against the verb's real column names first, since `picture_in_picture_batch()` takes `overlay` and `compare_videos_batch()` an `inputs` list-column. M58 added a second mechanism for the same vacuity, upstream of the assertion: a test HELPER that normalizes a call is blind to the case that exists to vary exactly what it normalizes — a `catch_call()` setting `run <- FALSE` on every call neutered the one case passing a malformed `run` on purpose, leaving it to assert the absence of an error the call no longer had. Such a helper fills in only what the case omitted (`if (is.null(args$x)) args$x <- default`), and every precedence case carries a CONTROL asserting the preempted error is live on that call — the control is what catches the vacuity when the helper is wrong.
- 2026-08-07 (M55): giving a package its `?<pkg>` landing topic has two traps, and the usethis template walks into one of them. - 2026-08-26 (M69): base R's `timeout =` bounds the WAIT, not the process — it escalates SIGINT at the limit, SIGTERM at +20 s and SIGKILL at +40 s, and `?system` says termination "works for typical commands, but is not guaranteed". A program that ignores the first two signals therefore outlives its limit by up to 40 s: an FFmpeg blocked on a writer-less FIFO under a 2 s limit aborts in ~2 s on macOS and ~42 s on Linux CI, measured on all three Ubuntu jobs. Any wall-clock assertion over a spawned program must budget limit + 40 s, per program, or it passes on the dev machine and reddens only on Linux — which cost M69 a full review return. The same arithmetic is why such tests `skip_on_cran()`: five of them is four minutes of a CRAN check spent waiting.
