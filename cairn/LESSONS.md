# Lessons
_Durable, append-only repo lessons (build quirks, testing tricks) — captured at milestone
end, surfaced at plan time. Capped at 50 lines (D-015); prune the least-useful when full.
Not status, not decisions (a choice is a D-entry); the false-green family is in
`references/false-greens.md` and the front-door guard-ordering family in `references/guard-ordering.md`._
- 2026-08-29 (M088): prose derived from executed calls still over-generalizes when every call it was derived from used a FRESH output path. `?separate_audio_video` and `NEWS.md` said a failed run leaves its output "absent" — true on a fresh path, false whenever that path already held a file, because Layer 1 removes what the run WROTE and never what it found (D046); review reproduced both halves and returned the milestone. The honest rule is per RUN, not per path: a stream-copy failure DOES remove a pre-existing output, because FFmpeg opened it before giving up. The replacement sentence then promised "its own error says which" — false at the time for the video half, whose condition `separate_audio_video()` discarded (corrected M090: it is now attached at `tm_video_error`). Derive a claim from calls spanning the state it quantifies over, and check that any promise about "the error" survives every path where that error is thrown away.
- 2026-08-29 (M087): a test that shells out to `git` must anchor on the checkout's OWN top level, not on `--is-inside-work-tree`. `R CMD check` runs the suite from an untracked copy at `<pkg>.Rcheck/tests/testthat`, and on GitHub Actions that copy sits INSIDE the workspace checkout — so the work-tree probe answers true while `git grep` (which searches TRACKED files from its own cwd down) finds nothing, and a sweep guard turns red for the environment rather than the defect. The mirror trap is the same grep run from `tests/testthat` without `-C`: it silently searches only that directory, so a repo-wide sweep passes vacuously and its non-empty-domain control passes off the test files themselves. Compare `rev-parse --show-toplevel` against the intended root, skip when they differ, and require a hit outside `tests/`. Both halves shipped green locally; only Linux CI saw either.
- 2026-08-06 (M52): R's character-based string functions are locale traps on text a process handed back. `strsplit(x, "", fixed = TRUE)` returns `NA` with only a WARNING when `x` is invalid in the session's `LC_CTYPE`, so whatever the caller derived from it vanishes silently; `sub()` on the same input errors outright. `useBytes = TRUE` fixes both wherever the separators are ASCII and preserves the original bytes — at the cost of dropping the string's UTF-8 `Encoding()` mark, a difference `identical()` and `expect_equal()` cannot see.
- 2026-07-30 (M45, consolidating M27): FFmpeg behavior differs by version and the two CI platforms straddle those differences — macOS brew ships 8.x, ubuntu-latest ships 6.1.1 — so "green locally, red on Ubuntu" is the signature. One instance paid for: per-stream metadata (`-metadata:s:v:0 title=`) became `name` on 8.x macOS and was absent on Ubuntu, so assert only on the stripped *output*, never an injected tag's *presence* (the adts muxer's version split, which cost seven M45 tests, is in `references/false-greens.md`). A separate platform failure is not the package at all: `pandoc: internal error: ARR_WORDS object (0x...) entered!` crashes vignette re-building on macos-latest arm64 and fails the job with `Status: 1 ERROR` while every test passed — re-run the job before reading it as a regression (M63).
- 2026-07-30 (M44): `cli::cli_warn()`/`cli_abort()` glue-interpolate EVERY bullet in the calling frame, so a bullet built with `sprintf()` from user data executes whatever braces that data contains — a path `my{video}.mkv` ABORTS the call ("could not evaluate cli expression") and `{n}.mkv`, naming a local of the message-building function, silently prints a filename that does not exist. Braces are legal in filenames on every platform. Route user data through a cli field (`{.file {x}}`), which does not recurse into the value, or `gsub("{","{{")` after the `sprintf()`; only a test over a brace-bearing path catches it.
- 2026-07-30 (M46, trimmed M69): R translates the `system(..., timeout =)` warning, so muffling or detecting a timeout by matching its English text is locale-dependent — under `LANGUAGE=de` it reads "Zeitüberschreitung bei Kommando ..." and the match fails, letting the warning through with the FULL command line and its temp paths in it. Key off the `status` attribute (124) instead. M69 built that into `R/timeout.R` and fenced THAT file with a guard that reddens on any text-matching call in it, so the uncovered remainder is any NEW timeout classification written outside it.
- 2026-07-30 (M47): a verb that STATES its stream selection must tolerate an input that lacks the stream type, because FFmpeg treats an unmatched `-map` as fatal, not empty. A bare `-map 0:a` exits 234 ("Stream map '' matches no streams") on a video-only input and a bare `-map 0:v` does the same on an audio-only one — both ordinary research files, and both cases where emitting NO map exited 0 and passed the stream through. Suffix the UNSELECTED specifiers with `?`; leave a specifier the caller NAMED strict, so a mistyped index stays an error instead of silently yielding a stream-less output. The suite caught only the video-only half, via one test that happened to use a silent fixture. **Corrected M49:** the `?` is safe only while ANOTHER map can still match — when EVERY specifier is optional and none matches, FFmpeg discards the maps and reverts to default selection (`-map 0:a:5?` on a video+audio file writes video AND audio), so on a verb emitting ONE map the `?` silently restores the very heuristic the map was added to remove. A one-map verb wants a strict specifier and a loud failure; a multi-map verb keeps the `?`. And `?` never covers a muxer that REFUSES a stream, only an absent one: `-map 0:v?` into `.wav` exits 234.
- 2026-08-06 (M53): fanning a NON-EXPORTED function out with furrr is correct in the shipped package and broken under `devtools::load_all()`: the worker rebuilds the closure's namespace by `loadNamespace()` from the INSTALLED library, so a source-only internal is `could not find function` and an installed one silently runs the installed version of your edits. `ffm_batch(parallel = TRUE)` is exempt (it maps the caller's own `.f`), and the suite cannot see it under the default sequential plan. Verify a new fan-out against a real `plan(multisession)` on an `R CMD INSTALL`ed copy, and pin the plan inside the tests.
- 2026-08-26 (M69): base R's `timeout =` bounds the WAIT, not the process — it escalates SIGINT at the limit, SIGTERM at +20 s and SIGKILL at +40 s, so a program that ignores the first two signals outlives its limit by up to 40 s (D056 holds the measured macOS and Linux figures). Any wall-clock assertion over a spawned program must budget limit + 40 s, per program, or it passes on the dev machine and reddens only on Linux — which cost M69 a full review return. The same arithmetic is why such tests `skip_on_cran()`: five of them is four minutes of a CRAN check spent waiting.
- 2026-08-29 (M089): `devtools::build_readme()` always reports a diff on `README.md` even when nothing changed — two knitted `ffm_compile()` outputs embed the input path, and `system.file()` resolves it inside a per-session temp library (`.../RtmpXXXX/temp_libpathXXXX/tidymedia/extdata/sample.mp4`), so the path differs on every run and every machine. At a consistency gate, check that the ONLY diff is those two `temp_libpath` lines and revert it; committing the churn buys nothing and the next run undoes it.
- 2026-08-30 (M090): a pre/post snapshot comparison answers "did anything at this path change?", not "did this run leave an output there". A FAILED run that had overwritten a file the caller already had leaves the two snapshots DIFFERENT, because Layer 1 removes what that run wrote (D046) and the caller's file goes with it — so the gate reported "written to" for a path now holding nothing. The three tests written for that gate all used a command that SUCCEEDED, varying only whether the file changed, so none could see that the predicate needed the run's outcome too. Where a predicate is a conjunction, the fixtures have to vary every conjunct; holding one constant across the whole family makes the family blind to it.
- 2026-08-30 (M091): two traps in measuring what a container will hold. (a) `ffprobe -select_streams a -show_entries stream=index` lists an MPEG-TS file's streams TWICE — once under its program and once globally — so a three-track `.ts` reads as six entries (or, with a trailing blank, four) where every other container reads three; count DISTINCT non-empty indices or a passing capacity check reads as a failing one. (b) A refusal at exit 234 under `-c:a copy` is not a capacity refusal: `.webm`, `.ogg` and `.opus` hold no AAC and refuse the copy, yet take three mapped streams under `-c:a libopus` — reading the first refusal as capacity is what left `.ogg` and `.opus` off the M091 gate and cost a review return. Before concluding a container holds one stream, re-run under a codec that container actually holds, and read FFmpeg's own wording (the genuine refusers name capacity: "Exactly one MP3 audio stream is required", "wav muxer does not support more than one stream of type audio").
- 2026-08-30 (M092): a milestone file's plan-owned line cap (<150, `cairn_validate` weight caps) is measured over the plan-owned sections only, and a ledger authored as one `###` sub-heading plus one table per item blows it fast — M092's Triage ledger over eight sections came to 96 lines and returned the milestone at review. One table with one row per item carries the same content, every id and reason verbatim, in 22 lines. Where a criterion says "one entry per X", a table row IS the entry; reach for the sub-heading shape only when an entry needs internal structure a cell cannot hold.
- 2026-08-31 (M094): a green fleet proves nothing about a path gated on hardware no runner has. Every `hardware = "nvenc"` behaviour is decided by `cached_encoder_names()`, and no CI runner (nor this machine) has an nvenc encoder, so the branch that runs when nvenc IS present executed nowhere in ten green checks — three review rounds and a suite of 11,310 assertions missed a refusal displacing the caller's own argument error there. Mock `cached_encoder_names()` to report the encoders present and re-run the assertion both ways; the same trick applies to any capability probe whose absent-answer path is the only one CI exercises.
- 2026-08-31 (M096): a sweep that computes its own domain by reading each function body for a spawn primitive must force that domain BEFORE `local_mocked_bindings()` replaces the primitives — inside the mocks no body names one and the domain silently halves (1530 cells to 705), and the leg asserting it equals `tm_timeout_domain()` stays green, since both sides shrink together.
- 2026-09-01 (M099): `withr::local_options()` keeps the FIRST of duplicate names where base `options()` keeps the last, so a blanket rename over `tests/` turns a test setting the OLD option name into one setting the new name twice — vacuous. Grep the tests for the old name that must survive a rename, and plant a shim that reads it to see red.
- 2026-09-01 (M097): one `R_USER_CONFIG_DIR` cannot hold `tools::R_user_dir()` and `rappdirs::user_config_dir()` apart: both read that envvar before any platform base, and on Windows rappdirs appends `appauthor/appname` where tools appends `R/<pkg>`, so `user_config_dir("tidymedia", "R")` and `R_user_dir("tidymedia", "config")` both resolve to `<root>/R/tidymedia` — distinct on macOS and Linux, identical there, so a "the two dirs differ" guard was green locally and red only on the windows-latest leg. Redirect the second library by a mock whose return value records its arguments; `rappdirs::user_config_dir(..., os = "win")` reproduces the layout locally.
- 2026-09-02 (M100), extended 2026-09-05 (M110): threading `call` into an EXPORTED function to fix a blame displacement must default it to `rlang::current_env()`, not `caller_env()` — under `caller_env()` internal callers still name the verb the user typed, so the pinning test passes, while a direct call is blamed on the caller's frame (`NULL` at the console, so the refusal names no function); only a direct call reaches that default. Threading it to the ABORT sites is half the job: `rlang::check_string()`/`check_bool()`/`arg_match()` each run on their OWN `caller_env()` default, so a wrapper's ARGUMENT refusal still names the internal function and puts the threading on display — `set_ffmpeg(x, confirm = "yes")` reported `Error in set_program("ffmpeg", location, confirm = confirm, call = rlang::current_env())`. Pass the threaded `call` into the checkers too.
- 2026-09-02 (M101): a consent seam that GATES on `rlang::is_interactive()` but ASKS with `utils::menu()` has two predicates, and they disagree — `rlang::local_interactive()` and `options(rlang_interactive = TRUE)` do not move `base::interactive()`, which is what `menu()` reads. Under `Rscript` the gate then opens and `menu()` throws an UNCLASSED `menu() cannot be used non-interactively`, carrying none of the documented remediation, exactly where the contract promises a classed refusal. No fixture had that combination: tests of the ask mock `menu`, tests of the refusal set `rlang_interactive = FALSE`. Route the asker's own failure through the same refusal.
- 2026-09-02 (M102): `archive::archive_extract()` leaves libarchive's connection open when the extraction fails mid-payload, and Windows refuses to delete an open file — so `on.exit(unlink(tf))` succeeds silently on macOS/Linux and leaves the download behind on Windows. The corrupt-payload fixture passed locally and failed `windows-latest` on `expect_false(file.exists(destfile))`; a well-formed header over a corrupt payload fails inside `archive_read_data_block()`, AFTER the file is opened, which the not-an-archive shape never reaches. Close the connection explicitly, and assert it with `showConnections()` before/after so the leak is visible off Windows.
- 2026-09-02 (M102): `utils::download.file()` returning status 0 is not a promise that a readable file arrived, and every reader below it then aborts UNCLASSED — `readLines()` with a bare `cannot open the connection`, `digest::digest(file = TRUE)` with a bare `simpleError`. Both escaped a condition-class census that walks a function's `return()` and `cli_abort()` nodes, because neither IS one: a census over exit NODES cannot see an abort raised inside a callee. Guard each reader, not the fetch.
- 2026-09-02 (M102): asking the disk what an extraction produced counts the PREVIOUS run's leftovers. `archive_extract()` does not clear its destination, so an installer whose directory is stable across runs registers binaries this run never unpacked — `file.exists()` over the expected paths reads TRUE either way. The extractor already returns the file list it wrote; intersecting THAT with what is required is the only reading that means "produced".
- 2026-09-02 (M102): a committed binary fixture needs two things `set.seed()` does not give it. 7z records per-entry mtimes the seed does not fix, so two generator runs a second apart differed by 6 and 8 bytes against the committed file — claim reproducible BEHAVIOUR plus a self-check, never byte-identity. And `.gitattributes`'s `* text=auto` rewrites the line endings of any fixture whose bytes happen to look like text (a 56-byte not-an-archive does), so binary fixtures need an explicit `*.7z binary`.
- 2026-09-03 (M103): `list.files(recursive = TRUE)` descends THROUGH a directory symlink, so a path it reports relative to `dir` is not guaranteed to name anything under `dir`. A cleanup removing what a before/after comparison shows was added then reads a created symlink as a created directory whose children are the link target's, and deletes them outside the directory it is about. `unlink(recursive = TRUE)` removes the LINK, so the escape opens only where that call fails — the platform a best-effort design plans for. Skip anything under a targeted directory the removal could not take.
- 2026-09-03 (M104): `Sys.which()` does NOT expand `~` and `file.info()` does, so a two-clause check over one path can be answering about two different files. A real 13-byte executable at `~/dir/bin/ffmpeg.exe` read back as `""` from the first and as a fine non-empty file from the second, so an install into a `~`-relative directory downloaded, verified and unpacked correctly and then refused itself, blaming the archive. Expand where the path is BUILT: expanding inside the check alone moves the same disagreement down to the caller below it.
- 2026-09-03 (M105): `Sys.which()` on Windows resolves to the 8.3 SHORT path, so `expect_identical(unname(Sys.which(f)), f)` is not a portable way for a test to assert "this file resolved" — `windows-latest` answered `...\FILE1B~2\empty.exe` for a path that had resolved fine. The premise assertion, not the code under test, was the CI failure. Assert what resolved rather than the string: a non-empty answer, the same `basename()`, and the size the case turns on.
- 2026-09-04 (M106): passing `NULL` as an argument through a `do.call()` grid needs `args["x"] <- list(NULL)`, never `args$x <- NULL` or `args[["x"]] <- NULL` — the latter two DELETE the element, so the call silently runs the function's own default for `x` instead of the `NULL` the cell meant to probe. The failure is invisible: the grid still returns a row, still compiles, and the sentinel arm reads exactly like the arm that never set the argument at all. Any generator crossing a sentinel over a call built as a named list has this trap; the tell is a sentinel arm whose outcomes match the default arm's everywhere.
- 2026-09-04 (M107): a comment asserting WHICH control-flow arm reaches a line is a derived claim, and reading the branch structure is not how you derive it. M107's own task was correcting a comment whose premise was false; the replacement shipped false twice over. `&&` short-circuits, so on the `fallback = FALSE` arm the predicate the comment credited with the refusal never runs at all, and on the `fallback = TRUE` arm the line it called unreachable is reached whenever the encoder IS present. One executed `resolve_hw_encoder()` call falsified each half in a second; neither is visible from the source. A milestone fixing a false comment is exactly where the next one gets written.
- 2026-09-05 (M108): stubbing a BASE-namespace function also stubs it for waldo, which testthat calls to build the diff for a failed comparison — so under a `dir.create()` stub any `expect_identical()` in the same test dies inside testthat's reporter instead of reporting its own result, and the traceback names the stub rather than the assertion. Split the claim across tests: keep the base-namespace stub in one that compares nothing (it can still assert which call was reached by the abort's name), and run the comparison expectations under the other stubs.
- 2026-09-05 (M109): building a jobs-COLUMN form of a test cell by duplicating the scalar row's arguments gives every row the same OUTPUT path, and a batch verb refuses colliding outputs BEFORE it reads the argument under test — four of seven members refused that way, so the sweep would have measured the collision guard rather than the thing it was written for. Tell the path columns apart by what the spec builder actually created on disk (inputs exist, outputs do not) and rename only the outputs, each on its own basename; a distinctness control checking within a column and not across them still lets two output columns collide.
