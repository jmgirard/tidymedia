# Lessons
_Durable, append-only repo lessons (build quirks, testing tricks) — captured at milestone
end, surfaced at plan time. Capped at 50 lines (D-015); prune the least-useful when full.
Not status, not decisions (a choice is a D-entry); the false-green family is in
`references/false-greens.md` and the front-door guard-ordering family in `references/guard-ordering.md`._
- 2026-09-09 (M119): two shipped-docs instruments report clean because they cannot see the thing. `R CMD build` and `devtools::build_vignettes()` copy the tree to a temp dir before knitting, so neither can observe a vignette chunk writing beside its sources — only an in-place `rmarkdown::render()` from `vignettes/` shows it. `urlchecker::url_check()` follows redirects silently and flags only failures, so it can never find a redirecting URL; `curl -IL` does.
- 2026-09-09 (M118, trimmed M119): `skip_on_cran()` cannot be measured by the runners you reach for. `devtools::test()` and `testthat::test_local()` both force `NOT_CRAN="true"` inside the run, so the CRAN branch never fires; `R CMD check` calls `test_check()` from `tests/`, which sets only `TESTTHAT_IS_CHECKING`. With `NOT_CRAN` unset the skip fires only when `!interactive()`, so a criterion over "NOT_CRAN unset" that does not name the session kind is unbounded.
- 2026-08-29 (M088), extended 2026-09-07 (M116), trimmed 2026-09-09 (M119): prose derived from executed calls still over-generalizes when every call it was derived from used a FRESH output path. `?separate_audio_video` and `NEWS.md` said a failed run leaves its output "absent" — true on a fresh path, false where one already held a file, since Layer 1 removes what the run WROTE, never what it found (D046); a stream-copy failure DOES remove a pre-existing output. The replacement then promised "its own error says which" — false for the video half, whose condition was discarded (corrected M090: now at `tm_video_error`). Derive a claim from calls spanning the state it quantifies over, and check any promise about "the error" survives every path that throws it away. One level down: a claim about a TEST composed from its comment and variable name rather than from what it calls — a test named for the `ffm_batch(manifest = TRUE)` caller called the shared callee twice and compared a literal against itself, three review returns coming of it. Instrument each advice bullet on its own: `"set_ffmpeg()"` is a substring of `"unset_ffmpeg()"`, so one assertion covered both and deleting either left the suite green.
- 2026-08-29 (M087): a test shelling out to `git` must anchor on the checkout's OWN top level, not on `--is-inside-work-tree`. `R CMD check` runs the suite from an untracked copy at `<pkg>.Rcheck/tests/testthat`, and on GitHub Actions that copy sits INSIDE the workspace checkout — so the probe answers true while `git grep` finds nothing, and a sweep guard reddens for the environment, not the defect. The mirror trap is that grep run from `tests/testthat` without `-C`: a repo-wide sweep passes vacuously and its non-empty-domain control passes off the test files. Compare `rev-parse --show-toplevel` against the intended root, skip when they differ, require a hit outside `tests/`.
- 2026-07-30 (M45, consolidating M27): FFmpeg behavior differs by version and the CI platforms straddle those differences — macOS brew ships 8.x, ubuntu-latest 6.1.1 — so "green locally, red on Ubuntu" is the signature. One instance paid for: per-stream metadata (`-metadata:s:v:0 title=`) became `name` on 8.x macOS and was absent on Ubuntu, so assert on the stripped *output*, never an injected tag's *presence*. A separate platform failure is not the package: `pandoc: internal error: ARR_WORDS object` crashes vignette re-building on macos-latest arm64 and fails the job with `Status: 1 ERROR` while every test passed — re-run before reading it as a regression (M63).
- 2026-07-30 (M44): `cli::cli_warn()`/`cli_abort()` glue-interpolate EVERY bullet in the calling frame, so a bullet built with `sprintf()` from user data executes whatever braces that data contains — a path `my{video}.mkv` ABORTS the call ("could not evaluate cli expression") and `{n}.mkv`, naming a local of the message-building function, silently prints a filename that does not exist. Braces are legal in filenames on every platform. Route user data through a cli field (`{.file {x}}`), which does not recurse into the value, or `gsub("{","{{")` after the `sprintf()`; only a test over a brace-bearing path catches it.
- 2026-07-30 (M46, trimmed M69, trimmed M119): R translates the `system(..., timeout =)` warning, so classifying a timeout by matching its English text is locale-dependent — key off the `status` attribute (124). `R/timeout.R` is fenced by a guard that reddens on any text-matching call inside it, so the uncovered remainder is any NEW timeout classification written outside that file.
- 2026-07-30 (M47): a verb that STATES its stream selection must tolerate an input lacking that stream type: FFmpeg treats an unmatched `-map` as fatal, not empty, so a bare `-map 0:a` exits 234 on a video-only input and `-map 0:v` on an audio-only one, where emitting NO map exited 0 and passed the stream through. Suffix UNSELECTED specifiers with `?`, leaving one the caller NAMED strict. **Corrected M49:** `?` is safe only while ANOTHER map can still match — with every specifier optional and none matching, FFmpeg discards the maps and reverts to default selection, so a ONE-map verb wants a strict specifier and a loud failure. And `?` covers an absent stream, never a muxer that REFUSES one (`-map 0:v?` into `.wav` exits 234).
- 2026-08-06 (M53): fanning a NON-EXPORTED function out with furrr is correct in the shipped package and broken under `devtools::load_all()`: the worker rebuilds the closure's namespace by `loadNamespace()` from the INSTALLED library, so a source-only internal is `could not find function` and an installed one silently runs the installed version of your edits. `ffm_batch(parallel = TRUE)` is exempt (it maps the caller's own `.f`), and the suite cannot see it under the default sequential plan. Verify a new fan-out against a real `plan(multisession)` on an `R CMD INSTALL`ed copy, and pin the plan inside the tests.
- 2026-08-26 (M69): base R's `timeout =` bounds the WAIT, not the process — SIGINT at the limit, SIGTERM at +20 s, SIGKILL at +40 s, so a program ignoring the first two outlives its limit by up to 40 s (D056 holds the measured macOS and Linux figures). Any wall-clock assertion over a spawned program must budget limit + 40 s, per program, or it passes on the dev machine and reddens only on Linux — which cost M69 a review return. The same arithmetic is why such tests `skip_on_cran()`: five of them is four minutes of a CRAN check spent waiting.
- 2026-08-29 (M089): `devtools::build_readme()` always reports a diff on `README.md` even when nothing changed — two knitted `ffm_compile()` outputs embed the input path, and `system.file()` resolves it inside a per-session temp library (`.../RtmpXXXX/temp_libpathXXXX/tidymedia/extdata/sample.mp4`), so the path differs on every run and every machine. At a consistency gate, check that the ONLY diff is those two `temp_libpath` lines and revert it; committing the churn buys nothing and the next run undoes it.
- 2026-08-30 (M090): a pre/post snapshot comparison answers "did anything at this path change?", not "did this run leave an output there". A FAILED run that had overwritten a file the caller already had leaves the two snapshots DIFFERENT, because Layer 1 removes what that run wrote (D046) and the caller's file goes with it — so the gate reported "written to" for a path now holding nothing. The three tests written for that gate all used a command that SUCCEEDED, varying only whether the file changed, so none could see that the predicate needed the run's outcome too. Where a predicate is a conjunction, the fixtures have to vary every conjunct; holding one constant across the whole family makes the family blind to it.
- 2026-08-30 (M091): two traps in measuring what a container holds. (a) `ffprobe -select_streams a -show_entries stream=index` lists an MPEG-TS file's streams TWICE, under its program and globally, so a three-track `.ts` reads as six; count DISTINCT non-empty indices. (b) A refusal at exit 234 under `-c:a copy` is not a capacity refusal: `.webm`, `.ogg` and `.opus` hold no AAC yet take three mapped streams under `-c:a libopus`, and reading that as capacity cost a review return. Re-run under a codec the container does hold, and read FFmpeg's wording — genuine refusers name capacity.
- 2026-08-31 (M094): a green fleet proves nothing about a path gated on hardware no runner has. Every `hardware = "nvenc"` behaviour is decided by `cached_encoder_names()`, and no CI runner (nor this machine) has an nvenc encoder, so the branch that runs when nvenc IS present executed nowhere in ten green checks — three review rounds and a suite of 11,310 assertions missed a refusal displacing the caller's own argument error there. Mock `cached_encoder_names()` to report the encoders present and re-run the assertion both ways; the same trick applies to any capability probe whose absent-answer path is the only one CI exercises.
- 2026-08-31 (M096): a sweep that computes its own domain by reading each function body for a spawn primitive must force that domain BEFORE `local_mocked_bindings()` replaces the primitives — inside the mocks no body names one and the domain silently halves (1530 cells to 705), and the leg asserting it equals `tm_timeout_domain()` stays green, since both sides shrink together.
- 2026-09-01 (M099): `withr::local_options()` keeps the FIRST of duplicate names where base `options()` keeps the last, so a blanket rename over `tests/` turns a test setting the OLD option name into one setting the new name twice — vacuous. Grep the tests for the old name that must survive a rename, and plant a shim that reads it to see red.
- 2026-09-01 (M097): one `R_USER_CONFIG_DIR` cannot hold `tools::R_user_dir()` and `rappdirs::user_config_dir()` apart: both read that envvar before any platform base, and on Windows rappdirs appends `appauthor/appname` where tools appends `R/<pkg>`, so both resolve to `<root>/R/tidymedia` — distinct on macOS and Linux, identical there, so a "the two dirs differ" guard was green locally and red only on windows-latest. Redirect the second library by a mock answering from its own subtree (corrected M113: it records nothing, it answers elsewhere); `rappdirs::user_config_dir(..., os = "win")` reproduces the layout locally.
- 2026-09-02 (M100), extended 2026-09-05 (M110), trimmed 2026-09-05 (M112): a `call` threaded to fix a blame displacement belongs on an INTERNAL taking it with no default, with each export a wrapper passing `rlang::current_env()` (D087; `test-exported-call-formal.R` now fails on an export that publishes one). Threading it to the ABORT sites is half the job: `rlang::check_string()`/`check_bool()`/`arg_match()` each run on their OWN `caller_env()` default, so a wrapper's ARGUMENT refusal still names the internal — `set_ffmpeg(x, confirm = "yes")` reported `Error in set_program("ffmpeg", location, confirm = confirm, call = rlang::current_env())`. Pass the threaded `call` into the checkers too.
- 2026-09-02 (M101): a consent seam that GATES on `rlang::is_interactive()` but ASKS with `utils::menu()` has two predicates, and they disagree — `rlang::local_interactive()` and `options(rlang_interactive = TRUE)` do not move `base::interactive()`, which is what `menu()` reads. Under `Rscript` the gate then opens and `menu()` throws an UNCLASSED `menu() cannot be used non-interactively`, carrying none of the documented remediation, exactly where the contract promises a classed refusal. No fixture had that combination: tests of the ask mock `menu`, tests of the refusal set `rlang_interactive = FALSE`. Route the asker's own failure through the same refusal.
- 2026-09-02 (M102): `archive::archive_extract()` leaves libarchive's connection open when the extraction fails mid-payload, and Windows refuses to delete an open file — so `on.exit(unlink(tf))` succeeds silently on macOS/Linux and leaves the download behind on Windows. The corrupt-payload fixture passed locally and failed `windows-latest` on `expect_false(file.exists(destfile))`; a well-formed header over a corrupt payload fails inside `archive_read_data_block()`, AFTER the file is opened, which the not-an-archive shape never reaches. Close the connection explicitly, and assert it with `showConnections()` before/after so the leak is visible off Windows.
- 2026-09-02 (M102): `utils::download.file()` returning status 0 is not a promise that a readable file arrived, and every reader below it then aborts UNCLASSED — `readLines()` with a bare `cannot open the connection`, `digest::digest(file = TRUE)` with a bare `simpleError`. Both escaped a condition-class census that walks a function's `return()` and `cli_abort()` nodes, because neither IS one: a census over exit NODES cannot see an abort raised inside a callee. Guard each reader, not the fetch.
- 2026-09-02 (M102): asking the disk what an extraction produced counts the PREVIOUS run's leftovers. `archive_extract()` does not clear its destination, so an installer whose directory is stable across runs registers binaries this run never unpacked — `file.exists()` over the expected paths reads TRUE either way. The extractor already returns the file list it wrote; intersecting THAT with what is required is the only reading that means "produced".
- 2026-09-02 (M102): a committed binary fixture needs two things `set.seed()` does not give it. 7z records per-entry mtimes the seed does not fix, so two generator runs a second apart differed by 6 and 8 bytes — claim reproducible BEHAVIOUR plus a self-check, never byte-identity. And `.gitattributes`'s `* text=auto` rewrites the line endings of any fixture whose bytes look like text (a 56-byte not-an-archive does), so binary fixtures need an explicit `*.7z binary`.
- 2026-09-03 (M103): `list.files(recursive = TRUE)` descends THROUGH a directory symlink, so a path it reports relative to `dir` is not guaranteed to name anything under `dir`. A cleanup removing what a before/after comparison shows was added then reads a created symlink as a created directory whose children are the link target's, and deletes them outside the directory it is about. `unlink(recursive = TRUE)` removes the LINK, so the escape opens only where that call fails — the platform a best-effort design plans for. Skip anything under a targeted directory the removal could not take.
- 2026-09-03 (M104): `Sys.which()` does NOT expand `~` and `file.info()` does, so a two-clause check over one path can be answering about two different files. A real 13-byte executable at `~/dir/bin/ffmpeg.exe` read back as `""` from the first and as a fine non-empty file from the second, so an install into a `~`-relative directory downloaded, verified and unpacked correctly and then refused itself, blaming the archive. Expand where the path is BUILT: expanding inside the check alone moves the same disagreement down to the caller below it.
- 2026-09-03 (M105): `Sys.which()` on Windows resolves to the 8.3 SHORT path, so `expect_identical(unname(Sys.which(f)), f)` is not a portable way for a test to assert "this file resolved" — `windows-latest` answered `...\FILE1B~2\empty.exe` for a path that had resolved fine. The premise assertion, not the code under test, was the CI failure. Assert what resolved rather than the string: a non-empty answer, the same `basename()`, and the size the case turns on.
- 2026-09-04 (M106): passing `NULL` as an argument through a `do.call()` grid needs `args["x"] <- list(NULL)`, never `args$x <- NULL` or `args[["x"]] <- NULL` — the latter two DELETE the element, so the call silently runs the function's own default for `x` instead of the `NULL` the cell meant to probe. The failure is invisible: the grid still returns a row, still compiles, and the sentinel arm reads exactly like the arm that never set the argument at all. Any generator crossing a sentinel over a call built as a named list has this trap; the tell is a sentinel arm whose outcomes match the default arm's everywhere.
- 2026-09-04 (M107): a comment asserting WHICH control-flow arm reaches a line is a derived claim, and reading the branch structure is not how you derive it. M107's task was correcting a false comment; the replacement shipped false twice over. `&&` short-circuits, so on the `fallback = FALSE` arm the predicate credited with the refusal never runs, and on the `fallback = TRUE` arm the line called unreachable is reached whenever the encoder IS present. One executed call falsified each half; neither is visible from the source. A milestone fixing a false comment is where the next one gets written.
- 2026-09-05 (M108): stubbing a BASE-namespace function also stubs it for waldo, which testthat calls to build the diff for a failed comparison — so under a `dir.create()` stub any `expect_identical()` in the same test dies inside testthat's reporter, and the traceback names the stub, not the assertion. Split the claim: keep the base-namespace stub in a test that compares nothing (it can still assert which call was reached, by the abort's name), and run the comparisons under the other stubs.
- 2026-09-05 (M109): building a jobs-COLUMN form of a test cell by duplicating the scalar row's arguments gives every row the same OUTPUT path, and a batch verb refuses colliding outputs BEFORE reading the argument under test — four of seven members refused that way, so the sweep would have measured the collision guard. Tell the path columns apart by what the spec builder actually created on disk (inputs exist, outputs do not) and rename only the outputs, each on its own basename; a distinctness control checking within a column and not across them still lets two output columns collide.
- 2026-09-05 (M111): a path in `.gitignore` is NOT out of the tarball — `R CMD build` ships whatever `.Rbuildignore` does not match, so an artefact can be invisible in `git status` and present in what CRAN receives. Maintain the two separately, and name the file the tool actually writes: testthat writes `tests/testthat/testthat-problems.rds` and `_snaps/`, never a `_problems/` directory, so M111's first line guarded a path nothing creates and review caught the real one still shipping.
- 2026-09-06 (M113): a sweep forcing a timeout over a computed domain must intercept at the RESOLVER, not only the spawn wrappers, once a member's spawning is conditional on the machine. `program_status()` probes a version only for a program it resolved, so on the macOS and Windows legs — which install no binaries — it spawns nothing and both sweeps go red for the runner, not a defect; green on every Linux leg and locally. Mock `find_program()` too, and give the grid a case under an emptied `PATH` with both config dirs empty.
- 2026-09-06 (M114), extended 2026-09-06 (M115): a doc chunk guarded on the verb's headline program can still start a second one — `extract_audio()`'s dropped-track check spawns FFprobe, so three vignette chunks guarded on FFmpeg alone started a program their guard never named. An instrument removing ALL candidates at once cannot see it, so measure program identity per chunk against the guard EXPRESSION. That instrument's own domain is the spawns it OBSERVES, so on a machine missing one program every chunk guarded on it drops out and an unguarded chunk starting it still reads clean — assert the binaries are present before sweeping, and abort on an empty domain. And `PATH` alone never hides a program here: `find_program()` falls back to a location remembered under `R_user_dir()`/rappdirs, so a build proving the guards must redirect `R_USER_CONFIG_DIR` and `XDG_CONFIG_HOME` and assert on `find_*()`, not `Sys.which()`.
