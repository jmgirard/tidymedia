- ~~`probe_all()` does not scale~~ — promoted 2026-07-31, split along the row's own two axes: axis (a) is **M52** and axis (b) is **M53**. Planning settled (a)'s output-format call by measurement, and against the row's own framing of it. The row offered `-of json` (jsonlite, not a dependency) or section markers; markers turn out to be a one-flag change but **breakable** — a title tag of `a\n[/STREAM]\nb` yields six bare close-markers for five streams, because the `default` writer escapes nothing. `-of compact` escapes `|`, newline, CR and backslash, so no value can forge a delimiter, and it needs no new dependency: it wins on robustness rather than on speed. Re-measured 2026-07-31 (ffmpeg 8.1.2, a 5-stream `.mkv`, ten copies): today 60 spawns / 1.700 s; markers 10 spawns / 0.267 s; compact 10 spawns / 0.358 s (~4.7x). Two costs the row did not name, both found at the criteria audit and both now in M52's scope: the compact writer emits `tag:`/`disposition:` where today's `default=nw=1` emits `TAG:`/`DISPOSITION:`, and each line leads with a keyless section field (`stream|…`, `format|…`, format **last**) — so "the schema is unchanged" needs active normalization, not just a different flag. Also confirmed: today's per-stream parse is *already* corrupted by a newline-bearing tag, so M52 fixes a latent bug rather than merely avoiding a new one. Original text: it is sequential over files (`R/ffprobe.R:72`) and `probe_one()` spawns **N+1 FFprobe processes per file** — one `-show_format`, then one more per stream in a `-select_streams` loop (`R/ffprobe.R:175`). Measured 2026-07-30 (ffmpeg 8.1.2, a 5-stream `.mkv`): 6 spawns / 0.239 s for one file, 60 spawns / 2.04 s for ten (0.204 s per file), where a single `ffprobe -show_format -show_streams -of json` returns all 5 streams in **0.020 s** — a ~10x cut on this file that widens with stream count. A 500-file corpus is ~3000 spawns and ~100 s today. Two independent axes: (a) collapse the per-stream loop into one call, which needs an output-format call — the loop exists because `-of default=nw=1` concatenates streams with no delimiter, so this means moving to `-of json` (a new parse path, and jsonlite is not currently a dependency) or to section markers; (b) parallelize across files, which needs a `parallel =` argument and the `future`/`furrr` seam D007 and D012 already established for `ffm_batch()`. (a) is the bigger win, is independent of (b), and changes no exported signature. Note `count_audio_streams()` already sidesteps `probe_all()` for exactly this reason (`R/ffprobe.R:111`, "which runs FFprobe once per stream"), so the cost is already acknowledged in-tree. — added 2026-07-30, promoted 2026-07-31 — user request; `R/ffprobe.R:60`, `:161`; D007; D012; M52; M53
