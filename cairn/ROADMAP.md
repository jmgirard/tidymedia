- `ffm_copy()` and `ffm_concat()` are no longer idempotent since M43 made `ffm_map()` append: a second `ffm_copy()` emits `-map 0` twice and duplicates every output stream (measured 2026-07-30: 1-video/1-audio input → 4-stream output), and `ffm_concat()` calls `ffm_copy()` internally so `ffm_concat() |> ffm_copy()` doubles too. Fix is small (`unique()` on the appended maps) but needs tests over the composite verbs M43's `≤1 -map` guard never covered. Promote on any report of a doubled output, or when the `audio_stream`-carry milestone next touches `ffm_map()`. — added 2026-07-30 — M43 review F2 (scored 76, logged); M43-D1; D023
- A bad codec *token* still leaks Layer-1's argument name on the verbs whose pipelines call `ffm_codec()` directly instead of the `apply_video_codec()` / `apply_audio_codec()` seams: `extract_audio(audio_codec = "a c")` reports "`audio` must be a single clean token" blaming `ffm_codec()`, where `anonymize_video` names `video_codec` and blames the verb (measured 2026-07-30). M41 fixed this class for non-string *values* only; tokens were never probed. - The dropped-audio-track check has no opt-out and its cost is all up front: every default-`audio_stream` call to `extract_audio`/`convert_audio` spawns an FFprobe process (0.041 s measured, against 0.187 s for `probe_audio()`), and the `_batch` verbs probe every unique input **serially, before `ffm_batch()`**, so the cost ignores `parallel = TRUE` and a large jobs table stalls before its first encode with no progress output. `suppressWarnings()` silences the message but does not skip the probe, and neither the four verbs' roxygen nor NEWS mentions the cost. Candidate shapes: a `check_tracks =` argument, an option seam, or probing lazily per row inside the fan-out — the last needs the `ffm_batch()` hook D024/RR02 Q3 rejected, so it would reopen that.
