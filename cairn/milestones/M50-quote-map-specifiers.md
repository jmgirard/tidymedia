# M50: Quote map specifiers in the compiled command string

- **Status:** review
- **Priority:** normal
- **Depends on:** M49

## Goal

Make the compiled command string paste-safe by quoting every map specifier, so
that M47's `-map 0:v?` stops failing when a reader pastes it into a shell.

## Scope

**In:** quoting the specifier element of every `-map` group in `ffm_groups()` —
the simple branch (`R/ffm.R:1299`) and the explicit-map line of the complex
branch (`R/ffm.R:1284`); the auto `[vout]` map at `:1283` is already quoted. A
D-entry stating which argument classes the *display* string quotes and why
execution cannot change. Re-baselining the test literals, the snapshot file,
and the rendered README.

**Out:** quoting codecs, pixel formats, seek values and raw output options →
new candidate row (the `display = opt` path at `R/ffm.R:1327` bypasses
`ffm_group()`'s quoting entirely and cannot express it without a signature
change). Any change to the *executed* argument vector. Handling a path that
itself contains a double quote — pre-existing, and orthogonal.

## Acceptance criteria

- [x] AC1 Every `-map` in a compiled command renders its specifier
      double-quoted, in both branches — asserted on a single-input pipeline
      (simple branch) and on an `ffm_hstack()` pipeline carrying an explicit

      it), that no `-map` in the compiled string is followed by an unquoted

- [x] AC3 The executed argument vector is unchanged: for each of those same

      (RB tripwire: irreversible-api)
- [x] AC4 No `-map` literal anywhere under `tests/testthat/` still expects the
      bare form; the three simple-branch `-map` lines in
      `tests/testthat/_snaps/ffm.md` (`:33`, `:82`, `:91`) are re-accepted;
      and the knitted command at `README.md:133` reflects the new form, having

**Actioned.**

- **F1 (92) — the durable record stated a count that is wrong.** D031, the AC2

Six findings scoring below 80 were actioned anyway, each a *verified* false
statement or logic defect on a line this milestone itself added — leaving them

- **F7 (70) — D031's "shell-free" claim was false.** `ffm_run()` reaches
  `system2(location, args = shQuote(args, type = quote_type))`
  (`R/program_management.R:113-121`), which does go through a shell on Unix; the
  safety comes from `shQuote`, not from avoiding one. The bullet now says so,
  and no longer claims the display renderer's style is the package's only
  quoting style — execution has its own.
- **F9 (78) — the new candidate row cited the wrong function.** It sent a future
  reader to `ffm_output_options()` at `R/ffm.R:1331`; the `display = opt` call is
  in the `output_opts` branch of `ffm_groups()` at `:1332`. Both corrected.
- **F4 (74) — the AC2 predicate misdiagnosed a map-less pipeline.** `length(s) >
  0 && all(...)` folded "emits no map" into the quoting check, so a future row
  like `extract_frame()` would have failed claiming it compiles a *bare*
  specifier. Split into two assertions, each naming its own offender.
- **F6 (68) — a fixture invocation was swept by the re-baselining.**
  `test-audio-stream.R:276` had become `-map "0"` inside a command FFmpeg
  executes, contradicting the T3 work log's statement that fixture commands were
  left alone. Reverted to the bare form, matching `helper-media.R`.
- **F14 (66) — the new snapshot scrubber was whitespace-bounded.** Its concat
  pattern could not match a path containing a space, so the parity test and the
  AC3 snapshot would have failed on Windows alone. Now bounded by the enclosing
  quote.
- **F13 (60) — a comment transcript went stale.** The header of
  `test-separate-av-multitrack.R` showed the bare form and said "the tests pin
  that form"; the transcript is kept in its pre-M50 spelling (it records what
  `b548902` produced) with a line saying the tests now pin the quoted one.
