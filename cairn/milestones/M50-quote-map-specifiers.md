# M50: Quote map specifiers in the compiled command string

- **Status:** review
- **Priority:** normal
- **Depends on:** M49
- **Driving RR:** —
- **Principles touched:** IP1
- **Branch/PR:** m50-quote-map-specifiers

## Goal

Make the compiled command string paste-safe by quoting every map specifier, so
that M47's `-map 0:v?` stops failing when a reader pastes it into a shell.

## Scope

**In:** quoting the specifier element of every `-map` group in `ffm_groups()` —
the simple branch (`R/ffm.R:1299`) and the explicit-map line of the complex
branch (`R/ffm.R:1284`); the auto `[vout]` map at `:1283` is already quoted. A
D-entry stating which argument classes the *display* string quotes and why
execution cannot change. Re-baselining the test literals, the snapshot file,
and the rendered README.

**Out:** quoting codecs, pixel formats, seek values and raw output options →
new candidate row (the `display = opt` path at `R/ffm.R:1327` bypasses
`ffm_group()`'s quoting entirely and cannot express it without a signature
change). Any change to the *executed* argument vector. Handling a path that
itself contains a double quote — pre-existing, and orthogonal.

## Acceptance criteria

- [ ] AC1 Every `-map` in a compiled command renders its specifier
      double-quoted, in both branches — asserted on a single-input pipeline
      (simple branch) and on an `ffm_hstack()` pipeline carrying an explicit
      `ffm_map()` beside the automatic `[vout]` map (complex branch).
- [ ] AC2 A test asserts, over every in-package pipeline the map-count
      invariant test enumerates (`tests/testthat/test-ffm.R`, as M49 leaves
      it), that no `-map` in the compiled string is followed by an unquoted
      token.
- [ ] AC3 The executed argument vector is unchanged: for each of those same
      pipelines, `ffm_args()` is byte-identical to the baseline T1 records,
      proving the change is display-only.
      (RB tripwire: irreversible-api)
- [ ] AC4 No `-map` literal anywhere under `tests/testthat/` still expects the
      bare form; the three simple-branch `-map` lines in
      `tests/testthat/_snaps/ffm.md` (`:33`, `:82`, `:91`) are re-accepted;
      and the knitted command at `README.md:133` reflects the new form, having
      been regenerated by `devtools::build_readme()` rather than hand-edited.
      `devtools::test()` is clean.
- [ ] AC5 A `cairn/DECISIONS.md` entry states the quoting convention: which
      token classes the display string quotes, that `ffm_group()`'s `quote=` is
      a positional index into `args` and not a level (`R/ffm.R:1174-1182`), and
      that `ffm_run()` executes `ffm_args()` and never the display string
      (`R/ffm.R:1160-1163`, `:1383`), which is why the change cannot reach
      FFmpeg. The entry also names the classes left bare and points at the
      candidate row.
- [ ] AC6 The roxygen prose that quotes a *compiled* map is corrected
      (`R/ffm.R:625`, `:626`); prose naming the bare `-map` option is left
      alone, being still true. `devtools::document()` produces no diff;
      `devtools::check()` reports 0 errors / 0 warnings; NEWS carries an entry.
