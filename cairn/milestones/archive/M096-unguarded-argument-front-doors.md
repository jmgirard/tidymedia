# M096: A wrong argument is refused by the verb, not by `purrr::pmap()` or after FFmpeg runs

**Status:** done (2026-08-31, PR #100 https://github.com/jmgirard/tidymedia/pull/100)

**Goal:** `segment_video(outfiles = 123)` was reported by `purrr::pmap()` and `ffmpeg_codecs(sort_by_type = "yes")` spawned FFmpeg before failing on an `if` — two arguments no front door guarded, and the instrument that would have found them corrupted only each member's first argument.

**Outcome:** `segment_video()` checks each `outfiles` element with `rlang::check_string()` (`R/ffmpeg.R`), below the existing length check and above `check_nvenc_available()`, so a build without nvenc cannot decide which of a caller's mistakes is reported; `arg` names the element (`outfiles[[2]]`) once there is more than one. `ffmpeg_codecs()` gained the `rlang::check_bool(sort_by_type)` `ffmpeg_encoders()` always had, above `resolve_timeout()`, so it no longer spawns FFmpeg on a call it should refuse. Behavior break, disclosed in `NEWS.md`: `ffmpeg_codecs(sort_by_type = 1)` returned a table before (`if (123)` is `TRUE`) and is now an error; covered by D014's pre-0.2.0 clean break. The instrument `tm_timeout_corrupt_specs()` widened from `args[[1]]` to member x formal x five wrong forms — 1530 cells, 1093 kept, 437 dropped, 0 mismatches — with `tm_corrupt_limit_sweep()` and the merge-base census `tm_corrupt_dropped_master()` (166 entries at 4063faa) new; the live sweep is compared to it as a two-way difference, counts pinned. `tm_outfiles_baseline()` records what `segment_video(run = FALSE)` compiled at the merge base. The narrow M094 leg retired into the widened one; M095's `test-nvenc-probe-blame.R` counts moved 496/234 to 499/231. `?tidymedia` and `NEWS.md` dropped `outfiles` from the per-row fan-out residual, leaving `ffm_batch()`'s `output` column and `anonymize_video_batch()`'s `pixel_format`/`color`.

**Decisions:** D076 (a fan-out verb's own argument is checked at that verb's front door; annotates D074 property 1, narrows D075's Scope sentence). Milestone-local: the gate booleans, `fallback`, `nvenc_available()`'s defaultless `call`, and `ffm_batch()`'s `output` column stay out, each dropped by measurement and named with its frame.

**Review:** Three-lens fan-out (user-facing tier). Blame-history and prior-PR-comments lenses: zero findings. Diff-bug lens: nine, ranked. Six fixed on the branch — the `ffmpeg_codecs()` NEWS entry (it claimed the call had always failed, false for a truthy value and hiding the break), the unindexed `outfiles` message, unpinned census counts (11 pairs carry two frames, so a regression could hide in the `setdiff`), two comments misattributing the domain collapse and the `-> :` census drop, `@param outfiles`, and a missing blamed-frame assertion in the AC3 test. One rejected as pre-existing (`normalize_audio_batch()`'s `channels`/`sample_rate` absent from the disclosure on master too). One to follow-up: `tm_outfiles_baseline()` has no committed generator, so the suite alone cannot tell a merge-base recording from a HEAD one — AC4 was instead re-measured live against a `4063faa` worktree at review.
