# M101: `install_on_win()` asks before it downloads and installs

**Status:** done (2026-09-02, PR #105 https://github.com/jmgirard/tidymedia/pull/105)

**Goal:** `install_on_win()` obtains the caller's consent — naming the archive it fetches, the directory it unpacks into, and the remembered locations it overwrites — before it creates, downloads, extracts or writes anything, and refuses rather than proceeds where no one can be asked.

**Outcome:** An internal `tm_confirm(prompt, ..., call)` seam asks via `utils::menu()` under `rlang::is_interactive()` and otherwise aborts with class `tidymedia_confirmation_unavailable` carrying the caller's own bullets; a `menu()` that cannot ask routes through the same refusal. `install_on_win()` gains `confirm = TRUE` last in its signature (`rlang::check_bool()` at the front door, D080), sited above the `dir.create()`, so a declined call creates, downloads, extracts and registers nothing and returns `FALSE`. `tm_install_details()` composes the resolved URL, the resolved install dir and each `<program>_location.txt` path, brace-escaped through the new `tm_cli_escape()` (M44), and feeds both the prompt and the refusal. The three registrations loop over one `tm_install_registers` vector, so the prompt cannot promise a different set of writes from the one the call makes. Roxygen names the default's `.7z` format instead of "zip", documents `confirm` and extends `@return`; `README.Rmd` and `NEWS.md` updated.
