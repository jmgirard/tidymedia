# M110: `set_program()` asks before it remembers a location

**Status:** done (2026-09-05, PR #114 https://github.com/jmgirard/tidymedia/pull/114)

**Goal:** `set_program()` and its four exported wrappers obtain the caller's consent — naming the file they write and the location they record — before creating a directory or writing anything under `tools::R_user_dir("tidymedia", "config")`, refuse rather than assume consent where no one can be asked, and say what they did.

**Outcome:** `set_program()` takes `confirm = TRUE` and `call = rlang::current_env()` as trailing formals, both threaded through `set_ffmpeg()`, `set_ffprobe()`, `set_ffplay()` and `set_mediainfo()`. `tm_set_details()`/`tm_set_prompt()` (beside `tm_install_details()`) build the consent prompt from the resolved `tm_config_file(program)` and the location as the caller typed it, through a cli file field — never the `Sys.which()` resolution, which is not what is written, and brace-safe against a location holding `{` or `{name}`. The `tm_confirm()` call sits above the `dir.create()`, so a decline or a non-interactive refusal (`tidymedia_confirmation_unavailable`, message naming `confirm = FALSE`) creates no directory and writes no file, and `forget_ffmpeg_capabilities()` is reached only on the write path. The call returns `TRUE` invisibly where it wrote and `FALSE` where the caller declined, replacing the `@return` M097 found false. A location with no executable aborts `tidymedia_program_not_found`, carrying `tm_program`/`tm_location` and a `call` naming the export the caller typed — the argument checkers included. `install_on_win()` registers with `confirm = FALSE`, its own prompt having already named all three overwrites. Breaking change; the pre-1.0 deprecation cycle was waived at the plan gate, and NEWS names the `.Rprofile` startup case.

**Decisions:** `call` stays a threaded formal on `set_program()`, against D074's siting paragraph, which has each export re-call the shared checker at its own front door. D074's mechanism cannot reach this seam: the no-executable abort and the consent refusal both sit below the config-path resolution and the prompt build, so re-calling them at four wrappers would duplicate both bodies. Falsified by a second seam wanting the same treatment, at which point the pair is a pattern worth a D-entry rather than two local departures.
