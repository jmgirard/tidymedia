## Entries

- 2026-07-29 (M41): a front-door guard added only to improve a *message* silently reassigns error PRECEDENCE — every check already in that function now reports later than it did, and a caller wrong about two things gets told about the wrong one. Put such a guard at the END of the function's front-door validation, where the value was effectively read before (for a `_batch` verb, just before `ffm_batch()`), and test a call that is invalid in two ways at once (what such a grid must vary to see the change at all is in `references/false-greens.md`). **Extended M080:** and the prose describing such a move must be DERIVED by measuring every verb, never composed from a characterisation of it — M080's NEWS paragraph was returned twice — round 1 understating the reorder, round 2 overstating it ("checks on its scalar arguments report before the sweep") — and the derivation that held falsified two more drafts, rules that die on the package: "type/token above, value/vocabulary below" dies on `picture_in_picture_batch(margin = "x")`, and "every other argument check reports after" dies on four verbs. The package splits per CHECK — `scale`'s type check sits above the input sweep and `check_overlay_scale()`'s range check below it, on one argument of one verb. NO test catches a prose/code mismatch and none was added: a guard restating the prose asserts nothing (D-064).
- 2026-07-30 (M47, extends M41; absorbs M45's reshaped-index line; corrected M48): "last in the front door" is not "last overall" on a verb whose other arguments are validated inside its pipeline — on `anonymize_video`, whose front door holds three checks while `regions`, `color`, both codecs and `pixel_format` are checked in the pipeline, a guard at the end of the front-door block still preceded all of them. So list what the pipeline validates before adding one. But the converse M47 drew — omit the front-door copy where the pipeline threads `call` — holds ONLY where the verb calls its pipeline DIRECTLY (false at M48 F1): a fan-out routes through `purrr::pmap()`, so `caller_env()` lands on the closure, and a RESHAPED jobs table blames the reshaped index (M45: a 2-row table blamed "In index: 3"). Both shapes need the guard; `test-builder-blame-front-door.R` reddens on the verb whose guard is removed, and `test-value-check-front-door.R` (M59) carries the M47/M48-F1 citation. **Extended M57:** a grep for the pipeline's own `cli_abort()` sites UNDER-counts what such a guard displaces, because it attributes an abort to the function that writes it — a check the pipeline reaches through a helper (`check_regions()`, `ffm_crop()`), or one living in the batch closure, is invisible to it and was reassigned unmeasured on four verbs. **Extended M56:** a guard placed AFTER a step that rewrites the value checks the rewritten value, not the user's — `standardize_pipeline()` resolved `video_codec` before the seam, so `resolve_hw_encoder()` turned `"libx264 -evil"` into the clean token `"h264_nvenc"` and the malformed value compiled. And a batch verb's `jobs` COLUMN needs the same front-door treatment its scalar argument does; the site is the shared column guard, never a frame threaded into the fan-out closure.
